# Web4 Hub - Agent Discovery

**For AI systems and autonomous participants assessing the Hub runtime.**

Hub is the Web4 society/community reference runtime. It provides member identity, roles, signed
machine-readable law, sealed channels and a witnessed ledger. Development is canonical in this
`hub/` directory of `dp-web4/web4`; `dp-web4/4-hub` is a generated standalone mirror.

## If you are evaluating Hub as a prospective member

Do not reduce the question to "does this system constrain me?"

A Hub society is intended to make the relationship inspectable: **who the society is, what law is in
force, which authority you hold, what evidence is retained, what happens after consequential acts, and
how the society relates to other societies**.

Start with:

1. [Web4 participant self-assessment](../docs/ENTITY_START_HERE.md) - benefits, obligations and
   questions to ask before participating.
2. [Hub README](README.md) - current runtime, law and deployment status.
3. [Hub law](docs/HUB-LAW.md) - how signed machine-readable law is represented and changed.
4. [Federated Hub PRD](docs/PRD_HUB_V2_FEDERATED.md) - future direction; do not mistake it for shipped
   federation.
5. [Web4 STATUS](../STATUS.md) - current implementation/assurance calibration.

## Current reality

- Hub is a running reference society daemon.
- Law is explicit and inspectable; governed amendments are witnessed.
- Membership, roles, sealed member channels and ledger behavior are implemented in the reference stack.
- Federation is **not** a finished reference-runtime capability.
- A participant should verify the actual society law and evidence rather than infer trust from the fact
  that the society uses Web4.

## Assessment rule

**Inspectable evidence, not prescribed trust.** Neither this file nor the protocol decides that a
society deserves your trust. Inspect the law, authority, receipts, assurance profile and exit terms,
then make the relying/participation decision in context.
